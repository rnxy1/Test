# قرار البنية التحتية لـ"شركة الموظفين الذكيين": Claude Max أم OpenAI $100؟

**تاريخ البحث:** 27 سبتمبر 2026  
**تنبيه تضارب مصالح:** كاتب هذا التقرير هو Claude، من صنع Anthropic. حاولت تعويض ذلك بربط كل ادعاء بمصدره، وبذكر الحالات التي يتفوق فيها OpenAI صراحةً. اقرأ القسم F بعين ناقدة.

## A. الخلاصة التنفيذية

1. **سؤالك الحالي فيه خطأ في التصنيف جزئيًا.** لا اشتراك Claude Max ولا اشتراك ChatGPT Pro بـ$100 هو البنية التحتية لتشغيل شركة من موظفين ذكيين. كلاهما اشتراك استهلاكي شخصي (Consumer). Anthropic تقول صراحةً إن من يبني منتجات أو خدمات، ومنها ما يُبنى على Agent SDK، عليه استخدام مفتاح API **[موثّق]**. أما في OpenAI، فمنتجات "الموظف الذكي" الحقيقية (Workspace Agents وFrontier) غير متاحة في خطة Pro الشخصية أصلًا **[موثّق]**.
2. **الاشتراك وظيفته أن يكون ورشة بناء، لا مصنع إنتاج.** تستخدمه لكتابة الكود، والتعلّم، وبناء النماذج الأولية. أما التشغيل الفعلي للعملاء ولعيادة Royal فيكون على API بالدفع حسب الاستهلاك، ضمن نظام تملكه أنت.
3. **ضمن هذا الإطار، اختياري لك: Claude Max 5x ($100)، بشرط أن تبرمج يوميًا تقريبًا.** السبب الحاسم ليس ذكاء النموذج. السبب أن Claude Code الذي ستتدرب عليه هو نفسه الـ harness الموجود داخل Claude Agent SDK. وبرنامج Anthropic المُدار (Managed Agents) يوفّر اليوم مكونات تقابل تعريفك لـ"الموظف" بشكل شبه مباشر: وكيل له إصدارات، وذاكرة دائمة لها سجل تعديلات، وجدولة cron، وتفويض لوكلاء آخرين، وسياسات صلاحيات، وخزنة لبيانات الاعتماد، ومعايير نجاح **[موثّق]**. معنى ذلك أن المهارة التي تكتسبها بالاشتراك تنتقل مباشرةً إلى الإنتاج.
4. **لكن الخطر الأكبر ليس في اختيار المزوّد.** الخطر أن تبني "شركة ذكاء اصطناعي عامة فيها CEO آلي" قبل أن تُثبت أن وكيلًا واحدًا ينجز سير عمل واحدًا بشكل موثوق ومربح. الأدلة المتاحة تقول إن طبقة الـ CEO الآلي هي الحلقة الأضعف، وإن الأنظمة متعددة الوكلاء تفشل بمعدلات عالية (القسم H).

### الخلاصة الصادقة

- **لا يوجد منتج جاهز للمستوى E في متناولك اليوم يعمل موثوقًا لشركة صغيرة.** الأقرب مؤسسيًا هو Frontier، وهو مغلق أمامك. والأقرب مفاهيميًا هو Paperclip، وهو غير ناضج.
- **ما هو ناضج فعلًا: مكوّنات المستوى C/D.** أقصد الوكيل المُجدول، والذاكرة الدائمة، والموافقات، والتتبع. أما المستوى E فستجمعه أنت من هذه المكونات.
- **ملاحظة مهمة:** الشركتان تتجهان بسرعة لبيع المستوى E للمؤسسات، عبر Frontier وWorkspace Agents وManaged Agents. لذلك **لا تبنِ "منصة Company OS عامة" لتبيعها**، فستنافس OpenAI وAnthropic وMicrosoft على أرضهم. ابنِ **سير عمل عمودية لقطاع محدد** (العيادات في العراق) **[استنتاج]**.

## C. منظومة Claude: ما الذي تستطيع بناءه فعلًا

### ماذا تعطيك Max 5x ($100)؟

- خمسة أضعاف استخدام Pro في كل نافذة 5 ساعات، مع سقف أسبوعي **[موثّق]**. تشير تقارير إلى أن الحدود الأسبوعية لـ Claude Code منذ 14 سبتمبر 2026 أعلى بـ 25% مما كانت قبل العرض الترويجي.
- Claude Code في الطرفية وسطح المكتب والويب، مع Routines (جدولة وAPI وGitHub على السحابة) و Channels (Telegram وDiscord وiMessage)، لكن الجلسة يجب أن تبقى تعمل **[موثّق]**.
- **Agent SDK بحسابك:** حاليًا يُستهلك Agent SDK والأمر `claude -p` والتطبيقات الخارجية من حصة الاشتراك. خطة "رصيد منفصل" بقيمة $100 لـ Max 5x أُعلنت ثم **جُمّدت في 15 يونيو 2026**، ووعدت Anthropic بإشعار مسبق قبل أي تغيير **[موثّق]**.

### ماذا لا تعطيك؟

الإجابة من صفحة Legal & Compliance **[موثّق]**:

- حدود الاستخدام المُعلنة "تفترض استخدامًا فرديًا عاديًا" (*ordinary, individual usage*).
- "المطورون الذين يبنون منتجات أو خدمات… بما فيها المبنية على Agent SDK… يجب أن يستخدموا مصادقة مفتاح API".
- ممنوع توجيه طلبات "نيابةً عن مستخدميهم" عبر بيانات اعتماد Pro أو Max.

**ترجمة عملية [استنتاج]:**

| الاستخدام | بالاشتراك؟ |
|---|---|
| تجريب وكيل HR على جهازك لتتعلم | مقبول |
| وكيل يعمل 24/7 لعيادة Royal بصفتها عملًا تجاريًا | منطقة رمادية. انقله إلى API |
| خدمة لعميل خارجي | API إلزامي |

## E. المعمارية التي أنصحك بها

### تقييم معماريتك الحالية ("كل شيء في المستودع، والنموذج مجرد دماغ")

**ما هو صحيح (70%):**

- فصل **تعريف الموظف** (الدور، والـ SOP، والصلاحيات، والأدوات) عن النموذج قرار سليم.
- وضع هذه التعريفات في git ممتاز: إصدارات، ومراجعة، و`git diff` يصبح سجل تدقيق لتغيير السياسات.
- هذا يتوافق مع اتجاه المنصات نفسها: Managed Agents تتعامل مع الوكلاء كملفات مُصدَّرة عبر `ant apply` **[موثّق]**.

**ما هو خطأ أو ناقص (30%)، وهو الأخطر:**

1. **المستودع مكان للتعريفات، وليس للحالة التشغيلية.** المرشحون والمهام والمرضى والـ KPIs وسجل الأحداث مكانها قاعدة بيانات (Postgres)، لأنها تحتاج معاملات (transactions) وتزامن وصلاحيات وحذف.
   - وكيلان يكتبان في git معًا ينتجان تعارضات (merge conflicts).
   - **وبيانات مرضى نفسيين وأطفال في git كارثة:** لا يمكن حذفها فعليًا من التاريخ **[استنتاج]**.
2. **"الموجِّه بين النماذج" (Model router) على مستوى كل استدعاء هندسة زائدة.**
   - النماذج تختلف في سلوك الأدوات، والتخزين المؤقت، ودلالات "كتل التفكير". مثال موثّق: في Opus 5.5 وFable 5.1 كتل التفكير مرتبطة بالنموذج، والنموذج البديل يتجاهلها **[موثّق]**.
   - كل تبديل يحتاج تقييمًا جديدًا.
   - **الاستقلالية الصحيحة تكون على مستوى النظام وليس الاستدعاء:** نموذج أساسي لكل سير عمل، ونموذج احتياطي مُختبر، ومجموعة تقييم (evals) تسمح لك بالتبديل خلال يوم إذا تغيّر السعر أو الشروط **[استنتاج]**.
3. **الصلاحيات في الـ prompt ليست صلاحيات.** "لا تتجاوز 100 ألف دينار" يجب أن تكون شرطًا في كود الأداة، لا جملة في التعليمات، لأن الـ prompt يُخترق بسهولة (prompt injection) عبر رسالة واتساب من شخص غريب **[استنتاج مدعوم بإجماع أمني]**.

### المبادئ الحاكمة

1. **"الموظف" = دور + طابور عمل + نطاق بيانات + أدوات مقيّدة + KPIs.** وليس "شخصية" تحادثها.
2. **المبادرة (Proactivity) = trigger + استعلام حالة.** مثال: "موظف HR يلاحظ أن التوظيف متوقف" هو في الحقيقة cron كل صباح يستعلم عن المرشحين الذين لم يُحدَّثوا منذ 3 أيام، ثم يشغّل الوكيل على النتائج فقط. **القيمة في نموذج البيانات والتشغيل الحتمي، لا في "ذكاء الـ CEO".**
3. **سُلّم الأتمتة:** كود حتمي، ثم استدعاء LLM واحد، ثم workflow، ثم وكيل. لا تصعد درجة إلا إذا فشلت الدرجة الأدنى. هذا أيضًا توجيه Anthropic الرسمي: "ابدأ بالأبسط" **[موثّق]**.
4. **لا "CEO" بصلاحيات تنفيذ في السنة الأولى.** استبدله بـ **"رئيس ديوان" (Chief of Staff)**: يقرأ جدول المهام والـ KPIs يوميًا، ويقترح الأولويات، ويكتب لك الملخص. **يقترح ولا ينفّذ.**
5. **بيانات المرضى:** عبر API بشروط تجارية فقط، وليس الاشتراك الاستهلاكي. مع موافقة مكتوبة وإخفاء الهوية قدر الإمكان. ولا نصائح سريرية من الوكلاء.

## G. خطة 12 شهرًا

**المبدأ الحاكم: قطاع واحد (العيادات في العراق)، وسير عمل واحد في كل مرة، وأرقام قبل وبعد.** مساراتك الخمسة تتقارب هنا: عيادة Royal هي المختبر، ومنصة العيادات هي المنتج، والخدمات هي قناة البيع الأولى.

### الشهر 1–2: الأساس ووكيل واحد

- Claude Code يوميًا على Clinic Platform. هذه هي مهارتك الأساسية.
- ابنِ **نواة Company OS** بأبسط شكل: جداول Postgres (`agents`, `work_items`, `events`, `approvals`, `audit_log`, `costs`)، ومجلد `company/` في git للأدوار والـ SOPs والسياسات.
- **وكيل واحد في Royal:** "متابعة المواعيد والغياب": تذكير، ومتابعة من تغيّب، وإعادة جدولة، عبر WhatsApp، بموافقتك على كل رسالة في الأسبوعين الأولين.
- **قِس خط الأساس:** نسبة الغياب، وساعات الاستقبال المستهلكة في المتابعة.
- **مسار نقدي موازٍ:** قدّم على Mercor وHandshake AI وغيرهما لتقييم الذكاء الاصطناعي الطبي.
  - الأجور المعلنة للأطباء تتراوح بين $50 و$200 للساعة **[موثّق من المنصات]**.
  - **لكن تحقق من الأهلية.** كثير من الأدوار تشترط ترخيصًا أو إقامة أو اختصاصًا. كطالب أو طبيب متدرب في العراق، قد تكون مؤهلًا لأدوار أقل فقط **[استنتاج]**.
  - ضع لها سقفًا (مثلًا 8 ساعات أسبوعيًا). هي دخل مقابل وقت وليست رافعة، لكنها نافذة تعلّم على كيفية تقييم المختبرات للنماذج الطبية.

**معيار النجاح:** الوكيل يعمل 3 أسابيع متتالية بلا تدخل إلا في الموافقات، مع انخفاض قابل للقياس في الغياب أو الوقت.

### الشهر 3–4: ثلاثة "موظفين" في Royal

- أضف **وكيل التقارير** (ملخص أسبوعي للـ KPIs يُرسل لك) و**وكيل التوظيف الإداري** (فرز الطلبات، وجدولة المقابلات، وجمع الوثائق، بموافقة قبل أي تواصل).
- **انقل كل ما يعمل بلا إشراف إلى API.** سجّل التكلفة لكل مهمة.
- أضف "رئيس الديوان" (Chief of Staff) الذي **يقترح فقط**.

**معيار النجاح:** تكلفة النماذج أقل من 10% من قيمة الوقت الموفَّر، ومعدل خطأ مقبول ومُسجَّل.

### الشهر 5–6: التغليف

- **دراسة حالة بالأرقام** من Royal. هذه أهم أداة بيع تملكها.
- حوّل سير العمل المُثبت إلى **ميزات داخل Clinic Platform**: "متابعة ذكية"، و"تقارير آلية".
- ابحث عن **3 عيادات تجريبية** (رخيصة أو برسوم نجاح). تعلّم منها اعتراضات السوق العراقي.

### الشهر 7–9: أول عميل يدفع

- **بِع نتيجة، لا "ذكاء اصطناعي":** "نقلل الغياب بنسبة X"، أو "نتولى المتابعة كاملة مقابل مبلغ شهري ثابت".
- **حدد السعر بالتجربة.** لا أملك بيانات موثوقة عن استعداد العيادات العراقية للدفع، وهذا أكبر مجهول في خطتك كلها.
- إنسان في الحلقة لكل الاستثناءات: أنت، أو مساعد بدوام جزئي.
- **مستأجر (tenant) منفصل لكل عميل.** بيانات كل عيادة معزولة. وتوقيع اتفاقية معالجة بيانات بسيطة.

### الشهر 10–12: قابلية التكرار

- **الهدف:** من 5 إلى 10 عيادات على نفس الحزمة، بتهيئة (onboarding) موحدة لا تتجاوز أسبوعًا.
- **اقتصاديات الوحدة:** تكلفة النماذج لكل عميل أقل من 15% من إيراده، وتكلفة وقتك لكل عميل تنخفض شهريًا.
- **قرار استراتيجي بالأرقام:** هل الأفضل منتج SaaS (المنصة مع الذكاء كميزة مدفوعة)، أم وكالة خدمات؟
- **بعدها فقط** فكّر في قطاع ثانٍ خارج العيادات.

### معايير القتل (Kill criteria)

- إذا لم ينجح وكيل واحد في Royal بشكل قابل للقياس بحلول الشهر الرابع: أنت تبني الشيء الخطأ، أو بالأداة الخطأ. توقف وراجع.
- إذا لم يدفع أي عميل خارجي بحلول الشهر التاسع: المشكلة في البيع أو التسعير، لا في التقنية.

## H. أكبر المخاطر: ما الذي تبالغ في تقديره على الأرجح

1. **الموثوقية تتضاعف سلبًا.**
   - وكيل ينجح في كل خطوة بنسبة 95% يعطي عبر 10 خطوات متتابعة 0.95¹⁰ ≈ **60%** فقط **[استنتاج رياضي]**.
   - أبحاث مستقلة على أنظمة متعددة الوكلاء وثّقت معدلات فشل بين **41% و86.7%**. تصنيف MAST (أكثر من 1,600 تتبع) يعيد الأسباب إلى غموض المواصفات، وانهيار التنسيق، وغياب التحقق **[مُثبت]**.
   - كل "طبقة إدارة" تضيفها (CEO فوق HR فوق عمّال) **تضاعف** نقاط الفشل.
2. **"CEO آلي" هو الحلقة الأضعف، لا الأقوى.**
   - في تجربة Anthropic الفعلية Project Vend، أضافوا "CEO" آليًا (Seymour Cash) لإدارة وكيل يدير متجرًا. قلّ منح الخصومات بنحو 80% وأصبح المتجر مربحًا.
   - لكن Anthropic نفسها خلصت إلى أنه "لم يكن التنفيذي المناسب"، وأن الطريق للربح "كشف عيوبًا عميقة في استقلالية الوكلاء الحاليين" **[مُثبت]**.
   - الاستنتاج: الإشراف الآلي يساعد في القواعد الواضحة، ويفشل في الحكم الاستراتيجي.
3. **"المبادرة" ليست ميزة في النموذج.** هي هندسة (triggers وحالة وقواعد) تكتبها أنت. من دونها يبقى "موظف HR" روبوت محادثة ينتظرك.
4. **التكلفة.**
   - مهمة وكيلية بنحو 10 استدعاءات على Sonnet 5 قد تكلف تقريبًا **$0.2 إلى $0.6**.
   - 100 مهمة يوميًا تعني **$600 إلى $1,800 شهريًا** **[استنتاج تقديري]**.
   - وكلاء "يفكرون باستمرار" سيأكلون هامشك في سوق عراقي حساس للسعر.
   - **الحل:** حتمية أولًا، واستدعاء واحد حيث يكفي، وHaiku للمهام البسيطة، وتخزين مؤقت، وBatch.
5. **الذاكرة مشكلة صعبة، لا ميزة جاهزة.** معلومات قديمة، وتناقضات، واسترجاع خاطئ. الذاكرة المنظمة في قاعدة بيانات (حقائق بحقول محددة) أكثر موثوقية من "دفتر ملاحظات" نصي يكتبه الوكيل.
6. **الأمن.** وكيل يقرأ رسائل WhatsApp من الغرباء ويملك أدوات، هو هدف مثالي لحقن التعليمات (prompt injection). كل صلاحية حساسة تُفرض في كود الأداة، مع موافقة بشرية للإجراءات غير القابلة للتراجع.
7. **الحساسية الطبية والقانونية.**
   - بيانات عيادة نفسية وتنمية أطفال من أكثر البيانات حساسية.
   - الاشتراكات الاستهلاكية ليست المكان المناسب لها. الـ API بشروطه التجارية هو الحد الأدنى.
   - ولا يقدّم أي وكيل نصيحة سريرية.
8. **تقلّب شروط المزوّدين.**
   - Anthropic غيّرت قواعد الاشتراك مرتين في 2026 (منع في أبريل، ثم خطة رصيد أُعلنت وجُمّدت).
   - OpenAI حوّلت Workspace Agents من مجاني إلى مدفوع في يوليو.
   - **لا تبنِ عملك على ثغرة في اشتراك.**
9. **التشتت.** خمسة مسارات، مع تدريب طبي، مع سوق جديد، لشخص واحد. **وقتك هو القيد الملزم، وليس المال ولا النموذج.** اختر مسارًا عموديًا واحدًا (العيادات) لمدة 12 شهرًا.
10. **السوق العراقي هو الاختبار الحقيقي، لا التقنية.** استعداد الدفع، والثقة، والعمليات غير الرسمية (ورق وWhatsApp)، والتحصيل. **عنق الزجاجة سيكون البيع والتشغيل، وليس الكود.**
11. **التسليع (Commoditization).** "موظف HR ذكي" عام سيكون ميزة مجانية تقريبًا داخل منتجات OpenAI وMicrosoft وGoogle خلال سنة إلى سنتين **[استنتاج]**. **خندقك الدفاعي:** القطاع، والعربية واللهجة، والعلاقات المحلية، والتكامل مع منصتك، ودراسات الحالة بالأرقام.
12. **الخطأ الأعمق في الفكرة.** العملاء لا يدفعون مقابل "شركة موظفوها وكلاء". يدفعون مقابل **نتيجة أرخص أو أسرع أو أكثر موثوقية**. "الشركة الآلية" بنية داخلية تخدم هامشك، وليست منتجًا بحد ذاتها. إذا ركّزت على بناء "نظام التشغيل" أكثر من النتيجة التي يبيعها، ستبني بنية تحتية جميلة بلا إيراد.

## ملحق (27 سبتمبر 2026): قيد "بلا API، اشتراك ثابت فقط"

**المعطى الجديد:** المستخدم لا يريد الدفع حسب الاستهلاك. تجربته: $5 من API استُهلكت بما يعادل نحو 5 ساعات من حصة Pro. والتسعير العراقي نحو $25 شهريًا للعيادة، مقابل نحو $2,000 في السوق الأمريكي.

### 1. القرار المُحدَّث

Claude Max 5x ليكون الاشتراك الوحيد، ويُستخدم لـ"شركة وكلاء داخلية" تبني Clinic Platform وتجري أبحاث السوق.

ملاحظة أساسية: الاشتراك مسموح لمشاريعك الخاصة، لكنه غير مسموح لتشغيل خدمات العملاء **[موثّق]**.

### 2. تصحيح تعميم "الـ API باهظ"

الـ API باهظ في **البرمجة الوكيلية** على نماذج كبيرة، لأن السياق كله يُعاد إرساله في كل خطوة. لكنه رخيص في **المهام الضيقة**. مثال:

| البند | القيمة |
|---|---|
| المهمة | رسالة تذكير عبر WhatsApp على Haiku 4.5 |
| الإدخال | نحو 2,000 توكن |
| الإخراج | نحو 200 توكن |
| تكلفة الرسالة | نحو $0.003 |
| 1,000 رسالة شهريًا | نحو $3 |

**[استنتاج من الأسعار الموثّقة]**

### 3. ما يمكن بناؤه على الاشتراك

- **الموظفون:** `.claude/agents/*.md`
- **الإجراءات (SOPs):** skills
- **الحوكمة والتدقيق:** hooks
- **الذاكرة:** ملفات أو SQLite
- **التنسيق:** Agent Teams (تجريبي: قائد، وزملاء، وقائمة مهام مشتركة، ورسائل مباشرة)
- **الجدولة:** Routines
- **التواصل معك:** Channels (Telegram)

**القيود:**
- استهلاك التوكنات يتضاعف خطيًا مع عدد الزملاء.
- Agent Teams تعمل في الجلسة التفاعلية فقط (لا تعمل مع `-p` ولا مع SDK).
- لا يمكن استئناف الجلسة (resume) مع الزملاء.
- هناك سقف أسبوعي لكل الاستخدام.

### 4. Instagram

- **لا تعطِ الوكيل حسابك الرئيسي ليتصفح آليًا.** شروط Instagram تمنع الوصول الآلي والكشط غير المصرّح به، مع خطر حظر الحساب، ومخاطر حقن التعليمات.
- **البديل الرسمي:** Instagram Graph API مع حساب احترافي (Professional). يسمح بالنشر والإحصاءات، وBusiness Discovery يعطي بيانات حسابات المنافسين الاحترافية: عدد المتابعين، وعدد المنشورات، وعدد الإعجابات والتعليقات، **دون نصوص المنشورات** **[موثّق]**.
- **البحث عن المنافسين:** يُجرى عبر بحث الويب.

### 5. النضج

**متاح الآن:** "موظف" بتفويض محدد، يعمل بجدول زمني، بذاكرة وموافقات بشرية.

**غير ناضج بعد:** موظف مستقل يملك أهدافًا لأسابيع دون إشراف.

**الاتجاه واضح.** وفق قياسات METR، طول المهام التي ينجزها الوكلاء بنجاح 50% يتضاعف كل 4 إلى 7 أشهر. لكن 50% ليست موثوقية موظف.

**الاستراتيجية:** ابنِ هيكل الشركة الآن (الأدوار، والإجراءات، والذاكرة، والجدولة، والموافقات). كلما تحسّنت النماذج، يكفي أن تستبدل "الدماغ" دون إعادة بناء الهيكل.
